# Docker

---

## 1. Core Concepts

*   **Image:** A read-only template containing application code, runtimes, libraries, and dependencies. The blueprint of a container.
*   **Container:** A running, isolated instance of an Image. It runs natively on the host kernel using Linux namespaces (isolation) and cgroups (resource limitation).
*   **Dockerfile:** A text file containing sequential instructions used to build a Docker Image.
*   **Docker Registry:** A storage and distribution system for images (e.g., Docker Hub, GitHub Packages, AWS ECR).
*   **Volume:** The preferred mechanism for persisting data generated by and used by Docker containers, decoupled from the container lifecycle.

---

## 2. Essential CLI

### Container Management
*   `docker run [OPTIONS] <image>` — Download (if missing) and start a container.
    *   `-d` (detached): Run container in the background.
    *   `-p host_port:container_port`: Map ports.
    *   `--name <name>`: Assign a custom name.
    *   `-v <volume>:<path>`: Mount a volume or bind-mount a directory.
    *   `--rm`: Automatically remove the container when it exits.
*   `docker ps` — List **running** containers (`-a` to show all, including stopped).
*   `docker stop <id/name>` — Gracefully stop a container (sends `SIGTERM`).
*   `docker kill <id/name>` — Forcefully kill a container (sends `SIGKILL`).
*   `docker rm <id/name>` — Remove a stopped container.
*   `docker logs -f <id/name>` — Stream container logs in real time.
*   `docker exec -it <id/name> bash` (or `sh`) — Open an interactive shell inside a running container.

### Image Management
*   `docker images` — List locally stored images.
*   `docker build -t <name:tag> .` — Build an image from a Dockerfile in the current directory.
*   `docker pull <image>` — Download an image from a registry.
*   `docker rmi <image>` — Remove a local image.

### System Cleanup
*   `docker system prune -a --volumes` — Remove all stopped containers, unused networks, dangling images, and optionally unused volumes.

## 3. Dockerfile Instructions & Optimization

*   `FROM`: Sets the base image (e.g., `python:3.11-slim`).
*   `WORKDIR`: Sets the working directory for subsequent instructions.
*   `COPY`: Copies files/directories from the host machine into the container.
*   `RUN`: Executes commands **during build time** (e.g., installing dependencies).
*   `ENV`: Defines environment variables.
*   `EXPOSE`: Documents which port the container listens on (informational only).
*   `CMD`: Specifies the default command to execute **at runtime**. Can be overridden via CLI arguments.
    *   *Note on `ENTRYPOINT` vs `CMD`:* `ENTRYPOINT` configures a container that will run as an executable. `CMD` provides default arguments to the `ENTRYPOINT`.

---

## 4. Basic Production-Ready Dockerfile Example

```dockerfile
# Stage 1: Build base with dependencies
FROM python:3.11-slim AS builder

WORKDIR /app

# Install system dependencies if needed
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    && rm -rf /var/lib/apt/lists/*

# Install python dependencies into a local prefix directory
COPY requirements.txt .
RUN pip install --no-cache-dir --prefix=/install -r requirements.txt

# Stage 2: Final runtime image
FROM python:3.11-slim

WORKDIR /app

# Copy installed dependencies from builder stage
COPY --from=builder /install /usr/local

# Copy application source code
COPY . .

# Expose port and define runtime command
EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
